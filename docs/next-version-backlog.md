## Modernization and ownership

Expo's [official upgrade guide](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/) recommends SDK upgrades one at a time, matching dependencies, and doctor checks; it also explains why current Expo Go is not a general solution for old SDKs. Use a controlled development build and consult each intermediate SDK's release notes. Do not jump directly to a new architecture while simultaneously changing data contracts.

Before any eventual release, establish ownership of Expo account `ssnl`, slug `wellping-app`, iOS bundle `app.wellping` / App Store ID `1532364388`, Android package `edu.stanford.ssnl.wellping`, signing keys, associated domains, and store listings (`app.json`, `eas.json`). Existing publishing docs describe legacy `expo publish` workflows and should not be followed unverified.
